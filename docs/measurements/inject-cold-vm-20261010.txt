WHAT THE WATCH FOUND INSTEAD, AND IT IS NOT THE WEDGE
------------------------------------------------------

Free physical memory falls about **16 KB per connection** and does not
come back:

    6248 -> 6068 KB over 11 polls, one connection each, perfectly linear
    6052 -> 5880 KB over 11 connections made back to back (-172 KB)
    5880 -> 5868 KB over 60 seconds idle with one connection (-12 KB)

So it tracks CONNECTIONS, not time: eleven in a few seconds cost the same
as eleven over eight minutes. At that rate a few hundred connections
would be the whole of a 32MB machine's headroom, and the probes connect
per run.

What this does NOT establish is where the memory went. `mem_free_kb` is
`dwAvailPhys`, and this project has already been misled by that number
once -- BACKLOG 2 records that the famous "28 KB free after a turn" was
the same field and never a hard wall. Win98 not returning pages to the
free pool looks identical from here to gremote not freeing them.

The test that settles it costs five minutes and was not run: stop
gremote, read free memory again. If it comes back, the memory was
gremote's and this is a leak; if it does not, it is the VMM's. Recorded
as BACKLOG 32 rather than guessed at here.
